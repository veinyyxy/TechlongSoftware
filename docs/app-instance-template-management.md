# 应用实例模板管理

## 目的

实例模板负责描述“某个产品的应用实例需要哪些配置”，但不负责执行部署。当前链路是：

```text
产品
→ 已发布模板版本
→ 套餐
→ 订阅 + 客户配置
→ Stripe 付款确认
→ pending 应用实例 + 配置快照
→ 管理员填写入口并手动激活
```

## 管理流程

1. 在“应用实例模板管理”创建归属于产品的模板。
2. 创建草稿版本，定义配置字段、默认值和部署流程标识。
3. 发布版本。发布后内容不可修改；变更必须创建新版本。
4. 创建套餐并选择同一产品下的已发布模板版本。
5. 在套餐限制中填写模板要求的限制项，例如 `访问人数限制=100`。
6. 为客户创建订阅时填写客户需求字段，例如店铺名称和主题风格。
7. 付款成功后，系统仅创建 `pending` 实例并复制模板版本与配置快照。
8. 管理员人工检查、填写 `access_url`、`tenant_key` 和域名/路径后手动激活。

## 配置字段

配置模式使用受验证的 JSON，当前支持：

- 类型：`text`、`select`、`number`、`boolean`、`color`
- 来源：`customer`、`plan_limit`
- `customer`：在订阅创建/编辑时填写。
- `plan_limit`：根据 `limitKey` 从套餐限制读取，前端提交值不会覆盖它。

示例：

```json
{
  "fields": [
    {
      "key": "storeName",
      "label": "店铺名称",
      "type": "text",
      "source": "customer",
      "required": true
    },
    {
      "key": "visitorLimit",
      "label": "访问人数限制",
      "type": "number",
      "source": "plan_limit",
      "required": true,
      "limitKey": "访问人数限制",
      "min": 1
    }
  ]
}
```

模板不得包含密码、令牌、凭据、私钥或 API 密钥字段。

## 不可变约定

- 已发布或已归档模板版本的内容不可修改。
- 套餐创建后不能更换模板版本；升级模板需要创建新套餐。
- 订阅生成实例后不能修改套餐或实例配置。
- 实例创建后不能更换产品、订阅、模板版本或配置快照。
- 旧实例可以没有模板版本和配置快照，作为兼容历史记录保留。

## 当前部署边界

`deployment_driver` 当前只允许 `manual`。`deployment_workflow_version` 只是受控版本标识。平台不会执行任意脚本、创建云资源、调用 Docker/Kubernetes 或自动修改餐饮订单系统代码。
