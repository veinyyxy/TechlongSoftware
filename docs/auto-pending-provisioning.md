# 支付后待开通实例操作说明

## 目的

当 Stripe 发送通过签名验证的付款成功事件后，平台会把付款记录标记为已付款、把该工作区的订阅更新为有效，并自动创建一条“餐饮订单系统”的待开通实例记录。该记录不是部署任务，也不会生成真实域名或入口。

## 管理员操作

1. 在“应用实例管理”中将状态筛选为“等待开通”。
2. 打开来源为“付款成功自动创建”的实例，核对企业客户和关联订阅。
3. 编辑实例，填写真实的 `access_url`、租户标识以及需要的域名或路径。
4. 返回详情页，确认有效订阅和有效访问地址都已具备后，选择“标记为已开通”。

也可以将记录标记为“开通失败”或“服务已暂停”。没有有效访问地址时，平台会阻止标记为已开通。

## 验收流程

1. 以普通企业账号从“订阅与账单”发起 Stripe 测试付款。
2. 用 Stripe CLI 转发测试 Webhook，或在 Stripe 测试事件中重新投递同一付款成功事件。
3. 确认付款记录为 `paid`、订阅为 `active`，并且该工作区只有一条餐饮订单系统实例，状态为 `pending`，来源为“付款成功自动创建”。
4. 重复投递同一事件，确认不会新增付款记录或应用实例。
5. 在管理员后台填写入口并标记为已开通；客户刷新后才会看到“进入餐饮订单系统”按钮。

## 边界

当前版本不部署应用、不创建云资源、不生成生产域名，也不支持同一个工作区购买多个餐饮订单系统实例。数据库以 `(workspace_id, product_id)` 唯一约束保证这一边界。
